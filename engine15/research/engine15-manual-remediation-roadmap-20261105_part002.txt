### Plan generation validation blocker (`E16`)

- **Observed:** Week Preview displays six requested running sessions and seven available days, but pressing Generate my plan yields `Choose supported goals for each discipline.` No successful new draft was shown.
- **Confirmed reproducible code path:** In `PlanBuilder.kt`, guided `runningRoute="fitness"` chooses `"General fitness"` and stores it as a `"run"` discipline goal. `Engine1Engines.goals["run"]` does not contain this value. `CoordinatedEngine1.generate` and `Engine15.validate` reject invalid discipline goals with the exact reported message. Do not claim that this was definitely the user's choice without capturing it.
- **Additional 5K evidence (2026-11-05):** User shows `Beat my personal best` with 5K selected and a subsequent Week Preview still carrying the message. `PlanBuilder.kt` maps race 5K `onContinue` to `"Improve 5K"`, which **is** supported. Therefore the consistency-route mapping is **a real separate code bug but an insufficient explanation for the reported 5K attempt**. Do not mark E16 diagnosed solely from that mapping.
- **Possible additional causes, unverified:** A stale hidden `disciplineGoals` key inherited from an existing plan or previous selections (the engine checks **every** map entry, including inactive disciplines); or a global `state.message` left over from the previous failed attempt. The banner appears on both Race Goal and Week Preview because `NativeMainActivity.kt` always renders it and it is reset only when a new repository operation starts. Screenshot alone cannot establish a new post-5K generation call or its result.
- **Diagnostic acceptance:** Use synthetic/fixture PlanRequests, log only the `goal`, active-discipline flags and sanitized `disciplineGoals` at validation (never secrets, emails, precise activity information). Reproduce valid 5K-only with fresh request; repeat 5K after prior fitness failure, returning Back, inherited old plan, and stray inactive goal entries. Assert errors are actionable, correctly scoped to the attempt and do not persist through unrelated screens. Confirm actual generated draft or actual failure event, not only banner state.
- **Required correction:** Establish a single source of truth for offered running goals and supported engine-policy goals; make the consistency/general-fitness route valid if explicitly intended, or provide an honest supported alternative rather than a silent replacement. Detect incompatible goals *before* final Generate and identify which one is incompatible.
- **Acceptance:** Exercise all offered running goal routes and mixed-discipline combinations on default Engine 1.5 plus explicitly selected Engine 1.0 fallback. Show saved draft with actual sessions after a valid request; assert invalid requests fail early with specific actionable feedback, no partial plan storage.

- Test source GPS, non-GPS, sparse/invalid samples, weak/offline network, old cache, multiple scale/density profiles, and attribution readability. **No OSM SDK/dependency or tile code has been implemented during this report.**
